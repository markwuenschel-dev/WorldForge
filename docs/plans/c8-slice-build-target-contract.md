Status: **ready** — §8 fork resolved: **Option C** (keep slice label + record real `ue_target` + enforce it). Executing task graph T1→T5.

## 1. Executive mission
Make the vertical-slice package evidence tell the truth about its UE build target.
Today `build_target="WorldForgeVerticalSlice"` names a UE target that does not
exist; RunUAT built the real `WorldForge` game target. Resolve the fiction and add
an enforceable check so a fictional target can never be reported again.

## 3. Strategic meaning
The package report is the sole committed proof of the build artifact (the binary is
not committed, §12 policy). A fictional `build_target` undermines exactly the
evidence an operator would trust. Fixing it — and enforcing it — restores the
report's integrity at its most load-bearing field.

## 4. Scope

the `SlicePackageReport` schema + its validator, the committed package report, and
(depending on §8) the 24 scenarios' `expected_build_target`. One enforceable check
that a reported UE target resolves to a real `Source/<name>.Target.cs`.

## 8. Human decisions required
**FORK C8 — which naming model?** (must be answered before implementation)

- **Option A — Collapse to the real target `WorldForge`.** Set every
  `build_target`/`expected_build_target` to `"WorldForge"`; regenerate the 24
  scenarios + manifest + package report; `ARCHIVE_DIR` may keep a slice-named dir.
  *Pro:* everything names the real UE target; no new build surface. *Con:* rewrites
  24 committed scenario files + manifest + report; drops the distinct "vertical
  slice" build identity. No UE rebuild needed (WorldForge already builds).
- **Option B — Make `WorldForgeVerticalSlice` real.** Add
  `Source/WorldForgeVerticalSlice.Target.cs` (a thin Game target over the
  `WorldForge` module); `package_slice` passes `-target=WorldForgeVerticalSlice`.
  *Pro:* every existing label becomes honest; keeps slice identity. *Con:* adds a
  C++ build-system file and **requires a UE build + re-package** to produce
  evidence under the new target (heavy, engine-dependent); grows build surface.
- **Option C — Keep the slice label; record the real UE target (RECOMMENDED).**
  Treat `expected_build_target`/`build_target` as the *slice* build-identity label
  (documented as such), pass `-target=WorldForge` explicitly to UAT, and add a new
  `ue_target` field to `SlicePackageReport` recording the actual UE target, plus an
  enforceable check that `ue_target` resolves to a real `Source/<ue_target>.Target.cs`.
  *Pro:* minimal; no 24-file rename; no new C++; **no UE rebuild** (re-emit via
  `--skip-build` over the existing Build/); adds the fitness-check the audit
  prefers. *Con:* introduces a second field (label vs. real target) that readers
  must understand.

**Recommendation: Option C.** It closes the fiction with the least ripple and the
strongest enforceable check, and needs no engine cycle. §9–§19 below are drafted
for Option C; the Option-A/B deltas are noted in §9.

## 9. Implementation strategy (decided shape: Option C)
Separate two concepts the code currently conflates: the **slice build-identity
label** (`build_target`, a slice-level name) and the **actual UE target built**
(new `ue_target`, which must resolve to a real `.Target.cs`). Make `package_slice`
explicit (`-target=WorldForge`) and record `ue_target` from that. Enforce that
`ue_target` is real in `validate_slice_package`, proven by a negative fixture.

*If Option A chosen:* replace T2–T4 with a single rename task (BUILD_TARGET →
"WorldForge" in `generate_slice_scenarios.py` + `slice_contracts.py` examples) +
regenerate scenarios/manifest/report; the enforceable check then applies to
`build_target` directly. *If Option B chosen:* add T0 = create the `.Target.cs`,
T4 passes `-target=WorldForgeVerticalSlice`, and a UE build+package replaces the
`--skip-build` verify (engine cycle required).
